# Separate owner management dashboard

The separate `/owner/` bundle preserves the existing dark-blue client visual system. It uses fixed same-origin `/owner-api` contracts, no fixture data in production source and no client BFF credentials. It is served only at the configured secure owner hostname under the default-off, development/test-only owner gate. The original `/dashboard/` bundle and its authentication controller are unchanged.

Screens implement owner overview, operators, client accounts, team/permissions and audit activity. They display actual authorized API responses. Operator metadata/status forms send version preconditions and fresh CSRF requests; entitlement controls only withdraw the two supported ceilings. Account creation, role promotion, invitation and grant restoration controls are deliberately absent. Directories are bounded/paginated; detail IDs and API response schemas are validated. UI permission checks only hide unavailable actions; the server independently enforces every action.

Owner identity/data are cleared on 401/403, logout, tab notices, identity switching and focus revalidation. Generation-bound callbacks and aborted loads suppress stale responses. Ambiguous mutations block further writes until explicit identity and record revalidation; there is no automatic retry. An uncertain logout is shown as uncertain, not as confirmed server invalidation. A secret-free session-storage denial marker prevents automatic reopening; offline logout cannot invalidate an HttpOnly server cookie, and future approved login must clear this marker only after a newly confirmed authentication ceremony.

There is no owner login/enrollment or real credential provisioning in this milestone. An unauthenticated browser sees an explicit unavailable/setup-required state. The real loopback HTTPS browser test uses synthetic, guarded database assurance fixtures and Secure/HttpOnly owner cookies; it does not demonstrate MFA enrollment. Existing client browser/security tests remain separate.

`npm run build` builds both independent bundles. `npm run test:frontend` covers components, lifecycle, contract validation and automated accessibility checks; automated contrast checking is excluded and still needs visual/manual review. The full disposable suite runs the actual HTTPS owner browser when Chromium and `VAULTX_BROWSER_TESTS=true` are available. No command here enables staging, creates accounts or changes deployment settings.
